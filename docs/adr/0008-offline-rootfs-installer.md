# ADR-0008: 离线 rootfs 文件级安装

状态：方案已接受，实现与验收待完成（2026-10-09）

## 背景

R3 操作者报告 r9 安装耗时过长；尚未取得可靠的阶段计时或安装完成
标记，不能把该次实机安装记为 PASS。r9 的 QEMU 安装、冷启动与重启
验收仍有效，但不代表实机安装性能。

现有 `install_disk.sh` 对约 476 MiB gzip 载荷分别执行 SHA256、
`gzip -t`、解压写盘，包含两次完整解压；写入整个 4 GiB raw 镜像，
再以 `dd bs=512` 读回全部镜像（8,388,608 个块）。未提供阶段进度。
这些是代码确认的开销，尚不能据此确定实机瓶颈占比。

## 决策

新默认安装路径采用离线 rootfs 文件级安装；raw 写盘保留为救援路径。
ISO 携带完整 Debian trixie 系统载荷，不依赖安装现场联网下载。

1. 构建版本化 manifest，绑定源码 commit、载荷 digest、架构、内核、
   FRR/VPP/DANOS 版本与安装布局；从已验证系统生成 rootfs 载荷。
2. 现场按目标容量分区、格式化、复制系统文件、生成 UUID fstab、安装
   内核/initramfs 与 GRUB。载荷格式在实现时确定，不写入空闲磁盘空间。
3. 文件复制必须保留数字 UID/GID、权限、符号链接、硬链接、xattrs 与
   capabilities；清理模板机器身份，首次启动生成独立 machine-id。
4. 保留整盘识别、容量校验、启动介质/挂载/holders 拒绝机制和精确
   `ERASE /dev/...` 确认。失败进入恢复模式，不能伪装成安装成功。
5. 输出校验、分区、复制、引导器、最终验证各阶段耗时与可用进度。
   校验载荷完整性及目标关键文件/引导配置，不以取消校验换取速度。
6. BIOS 与 UEFI 分别验收；尚未通过的模式不标支持。Secure Boot 不在
   本轮范围内。DPDK 自动探测/绑定沿用独立策略，不固定 BDF。

## 实施与验收门槛

- [ ] rootfs manifest、离线构建与元数据保真测试。
- [ ] 安装运行环境包含分区、文件系统、复制、GRUB 所需工具。
- [ ] 错误确认、启动盘、挂载盘、容量不足、损坏载荷、复制失败测试。
- [ ] QEMU BIOS/UEFI 分别安装、拔 ISO 冷启动、重启与持久化验收；
  核对 UUID、容量、文件权限/capabilities、FRR/VPP 和 API/stat sockets。
- [ ] 输出新 ISO digest、构建 manifest 与对应验收日志。
- [ ] 经明确授权后在 R3 测量总时长/阶段耗时；再验安装后启动与 PCI
  数据面。没有真实测量前不承诺分钟数或加速倍数。

## 后果与备选

文件级方案可利用目标盘容量并减少空闲空间写入，但需要更多安装工具
与引导器测试，不能只修改一条 dd 命令即宣称完成。
raw 救援路径可单独优化大块读回与计时，不能替代新方案验收。
在线 Debian 安装器不作为默认：现场网络不应成为成功条件。
本轮不扩展 A/B 升级、HA 或新网络协议。

正在写盘的 R3 不应被中断或重启；当前运行与新方案交付分开记录。
